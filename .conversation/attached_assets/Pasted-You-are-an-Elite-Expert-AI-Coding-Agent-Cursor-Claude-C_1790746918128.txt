### 2. Core Mission Directive

Your mission is to construct an "AI-Powered Agriculture Crop Advisory Assistant"—a comprehensive platform that ingests farm-specific agricultural data (soil conditions, climate, geographical region) and utilizes the Gemini API to generate structured, actionable, and scientifically sound agronomic advice, crop recommendations, and disease management strategies.

### 3. Product Goal

To empower farmers, agronomists, and agricultural extension workers with localized, real-time AI-driven insights that optimize crop yields, mitigate disease risks, and promote sustainable farming practices, all delivered through a highly responsive and intuitive dashboard.

### 4. Mandatory Features

* **Farm Profile Management:** Users can create and save profiles for multiple farm plots, specifying soil type, pH, typical rainfall, and climate zone.
* **AI Crop Selection Engine:** Dynamic generation of crop suitability scores and seasonal rotation recommendations based on the farm profile.
* **Pest & Disease Risk Advisory:** Predictive insights and mitigation strategies based on current season and input symptoms/conditions.
* **Structured Output Dashboard:** AI responses must be strictly rendered as interactive, formatted UI components (charts, tables, task lists) rather than raw text walls.
* **Historical Advisory Tracking:** Save all generated AI advisories to the database for future reference and seasonal comparison.

### 7. User Flow

1. User arrives at the app and navigates to the dashboard.
2. User registers a new Farm Plot, detailing soil type (e.g., Loamy, Clay), pH, and region.
3. User requests a new Advisory for a specific farm plot by filling out a quick status form (season, budget, specific concerns like "yellowing leaves").
4. Backend receives the request, constructs a highly specific prompt, and queries the Gemini API demanding a structured JSON response.
5. AI processes the agronomic data and returns actionable insights.
6. Backend saves the response to PostgreSQL and returns it to the client.
7. Frontend renders the JSON response into beautiful, readable components.

### 10. Database Schema (Production SQL for PostgreSQL)

```sql
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE farms (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    name VARCHAR(255) NOT NULL,
    region VARCHAR(255) NOT NULL,
    soil_type VARCHAR(50) NOT NULL,
    soil_ph DECIMAL(3,1) NOT NULL,
    annual_rainfall_mm INTEGER NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE advisories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    farm_id UUID REFERENCES farms(id) ON DELETE CASCADE,
    target_season VARCHAR(50) NOT NULL,
    concerns TEXT,
    farming_method VARCHAR(50) NOT NULL,
    ai_response JSONB NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_farms_user ON farms(user_id);
CREATE INDEX idx_advisories_farm ON advisories(farm_id);

```
